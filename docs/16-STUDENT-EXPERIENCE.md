# Student Experience

## Primary journey

```text
Login
→ Home
→ Continue Learning
→ Lesson
→ Ask AI / Practice
→ Assignment
→ Revision
→ Build Project
→ XP / Badge
→ Progress
```

## First login

- Explain five core actions.
- Confirm profile/class enrollment.
- Show local/privacy status in simple language.
- Explain the tutor honestly: it is an AI, it can be wrong, it gives hints on homework, and messages suggesting someone may be in danger are shared with a trusted adult at school (`41`).
- Avoid configuration complexity.

## Home priorities

1. What should I do next?
2. What is assigned?
3. Can I ask for help?
4. What progress have I made?

## Empty states

A new student with no enrollment should see teacher/class guidance, available self-paced pathways if allowed, and a clear Ask/Explore option—not an empty analytics dashboard.

## Offline state

Use positive wording: `Local learning available. Internet services are currently unavailable.` Do not show alarming error banners when the user can continue normally.

## Error states

- Model busy: queue/retry with useful alternatives.
- Code runner unavailable: preserve work and explain.
- Resource index unavailable: allow browsing cached metadata if possible.
- Storage low: student-facing message should be minimal; admin gets actionable detail.

## Accessibility

Support keyboard navigation, readable typography, dyslexia-friendly options where feasible, captions/transcripts for future audio, reduced motion, and clear language.
