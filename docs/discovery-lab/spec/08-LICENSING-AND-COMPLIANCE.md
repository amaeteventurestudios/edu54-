# 08 MIT / Apache-2.0 commercial licensing policy

The founder accepts **only MIT or Apache-2.0** bundled third-party code, commercially usable and rebrandable. This is a stricter **product-selection rule**, not a claim that other OSS licenses prohibit commerce. GitHub visibility is not a license grant.

Before adoption pin a commit and inspect LICENSE, NOTICE, package/dependency trees, embedded sources, graphics, 3D models, datasets, educational lesson text, questions, icons, fonts, sound effects, sample music and AI models. Code license does **not** grant media/content rights. Unknown/noncommercial/copyleft/proprietary-without-explicit-commercial-grant = blocked by project policy. Record approved SHA, license text, notices, dependency SBOM, asset provenance, review date and incorporated paths in a machine-readable registry.

MIT/Apache software can be redistributed commercially **subject to notices and other conditions**. Keep copyright and license attributions; Apache NOTICE and relevant modified-file notices where required. Branding of upstream trademarks is separate from code rights. Music exercises should use original, public-domain or specifically cleared material. Re-review licenses on every upgrade, and run a final release audit. Seek qualified legal review for commercial launch.
