# Impact Measurement

## Purpose

Sponsors and program leaders need evidence of use and outcomes without creating invasive student surveillance.

## Deployment metrics

- labs deployed;
- schools/libraries/community sites served;
- active devices;
- uptime and reliability;
- teacher onboarding completion;
- support incident volume/time-to-resolution.

## Learning activity metrics

Prefer local/aggregate reporting where possible:
- active learners;
- lessons completed;
- courses completed;
- coding projects completed;
- revision sessions;
- AI learning sessions (count only, never content; not used as a success target, see `15`);
- teacher-created/assigned materials;
- badges/mastery milestones.

## Economic metrics

- estimated commercial subscription cost avoided under clearly stated assumptions;
- hardware reuse value;
- deployment cost per active learner/site.

## Privacy

Do not centralize raw prompts merely to make dashboards interesting. Aggregate metrics should be designed explicitly and documented.

## Evaluation maturity

Distinguish usage metrics from learning outcomes. If Umanah later claims educational gains, use appropriate pre/post measures, comparison design, or independent evaluation rather than inferring learning from engagement alone.
